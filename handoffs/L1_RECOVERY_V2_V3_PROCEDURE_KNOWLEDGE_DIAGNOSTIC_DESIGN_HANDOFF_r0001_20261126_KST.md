## 1. 문제 및 목적
사용자가 실제 Recovery를 시험한 결과 유사 경로 탐색(V3), 보호 로직·수정 방안(V4/V5), MSC 품질에 문제가 있었으며 V2 원인 규칙부터 부정확할 가능성을 제기함. 실제 실패 PR/CL, 실행 로그, 활성 스킬 revision은 아직 확보하지 못함. Qwen3.6-27B의 추론 한계, 코드 분석 도구 결손, 전체 Procedure 이해 부족, Recovery 오케스트레이션 결손을 구분할 것. 전체 L1 지식 구축을 선행 조건으로 가정하지 말 것.

## 2. PR/CL 입력부터 단계별 진단
| 단계 | 확인할 내용 및 산출물 |
|---|---|
| V0 | 기존 비-timeout Seed 1건, Jira/PR, 수정 전후 및 현재 revision/build, 소스 경로, 활성 스킬/action/실행 영수증 고정 |
| V1 | 증상·발생 조건·실패 인과·Fix 효과를 원본 diff 및 주변 코드로 검증. Jira 주장과 코드 사실 구분 |
| V1→V2 | 수정 함수가 속한 정상 Procedure의 시작/종료, 호출·메시지 순서, 모듈 책임, 상태 전이, 객체/세대/자원 소유권, 필수 순서와 정상 불변조건 확인. 비동기/실패 분기 및 근거 누락 명시 |
| V2 | 최초 위반, 필수 전제, 보호 시점 및 기대 상태를 원인 규칙으로 구조화. 수정 전 실패·수정 후 보호·정상 반례의 원본 대조. 불충분하면 확정하지 않음 |
| V3 | 규칙을 API/caller/callee, 상태 읽기·쓰기, 메시지/등록/dispatch, 공유 자원 및 소유 경계의 탐색 조건으로 변환. 실제 Analyzer 호출, 후보·제외·미조사·잘림 및 탐색량 기록 |
| V4/V5 | 후보별 최초 위반 이전 보호 효력, 우회 분기, 검출 신호, 복구 소유자·위치·복귀 조건·실패 처리 검증. 기존 Fix의 무조건 복제 금지 |
| V6 | 검증된 Scenario IR로 AS-IS/TO-BE MSC 생성, doc-converter 실제 호출 및 방향·순서·분기 의미 대조. 기존 Work/Viewer 재사용 |

## 3. 원인 분리 실험 (r0007의 서브에이전트 A/B/C와 별개)
동일 PR, 현재 revision/build, Qwen 모델/설정, 탐색 범위·예산 및 수락 기준으로 비교. 각 실행은 독립 맥락을 사용하고 평가 정답을 입력에 노출하지 않음. 가능한 경우 반복하여 변동성 기록.
| 조건 | 입력 |
|---|---|
| D0 | 현행 Recovery 기준선 |
| D1 | 검증된 코드 분석 fact만 추가 |
| D2 | 검증된 정상 Procedure Knowledge만 추가 |
| D3 | D1+D2 |
D1 개선은 코드 사실 획득/전달 문제의 단서, D2 개선은 Procedure 맥락 문제의 단서. D3에서도 실패하면 단계 지침·도구 사용·추론 한계를 추가 분리(동일 입력의 강한 모델 비교 포함 가능). 입력 중복 및 지식에 정답이 섞이는 교란을 통제하며 단일 시험으로 원인을 확정하지 않음.

## 4. 최소 Knowledge 파일럿
Seed 관련 Procedure 하나만 선정. 기존 l1-knowledge-updater 및 code-analyzer, doc-converter의 실제 계약을 확인하여 정상 동작 지식을 생성하거나 검증된 기존 지식을 재사용. Module/Feature/Procedure/Scenario 교차 참조, 정상 MSC, 모듈 책임, 상태·소유권·순서 불변조건, 분기, source revision/build 및 코드 근거를 포함. Recovery는 필요한 범위만 읽고 현재 코드와 대조. 오래되거나 충돌하는 지식은 가설로만 취급. 그룹 게시·전체 지식 구축은 별도 결정.

## 5. 평가 및 설계 GPT 요청
- 담당자가 검증한 원인 규칙/기대 후보/정상 반례를 평가용으로 별도 고정. V1 fact 정확도, V2 필수 전제·최초 위반 정확도, V3 기대 후보 recall/precision·미조사량, V4 잘못된 종결, V5 조치 타당성, V6 MSC 의미 오류를 비교.
- 실제 실패 결과와 활성 스킬을 먼저 확보하고, r0007에 이미 존재하는 검증 규칙이 실행되지 않은 것인지 규칙 자체가 부족한지 대조.
- D0~D3 시험 설계, 최소 Procedure Knowledge 구조 및 조회 계약, 단계별 입출력/실패 재개점, 담당 스킬별 최소 변경안과 수락 기준을 제안. 필요 시 반복 오류 단계만 선택적 위임 검토.
- 설계 GPT의 첫 회신: 원인 가설/필요 증빙/비교 시험표/변경 후보/우선순위. 근거 없는 모델 한계 단정 및 선제 전체 지식 구축 금지.
- Recovery/Analyzer/Updater/Converter 책임을 유지하고 Kernel/Viewer 내부 변경은 별도 작업으로 분리. 업무 소스와 상세 결과는 업무 Work에만 보존.

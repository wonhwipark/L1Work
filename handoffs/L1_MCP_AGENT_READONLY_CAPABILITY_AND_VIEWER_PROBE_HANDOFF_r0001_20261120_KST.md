# 업무 GPT 요청 — Agent에서 확인 가능한 Linux MCP 읽기 전용 진단 확장

r0001 / 2026-11-20 KST / 설계·개발·시험 인계

## 1. 요청 목적과 입력

업무 GPT가 현재 실제 동작을 직접 확인할 수 없어요. 사용자가 모바일 Agent에서 ‘Viewer 연동 상태 확인해줘’라고 요청하면 기존 Linux MCP가 실제 대상 호스트의 설치·연결·문서/MSC 조회 상태를 근거와 함께 한 번에 답할 수 있도록 기존 기능을 확장해 주세요. 업무 GPT는 현장 계약 확인·개발 지시·결과 판정을 맡고, 허용된 Linux 로컬 Agent/업무 LLM이 개발·시험을 수행해요.

- 전달 저장소: wonhwipark/L1Work, branch main
- 이 문서: handoffs/L1_MCP_AGENT_READONLY_CAPABILITY_AND_VIEWER_PROBE_HANDOFF_r0001_20261120_KST.md
- 연계 변경서: [Viewer UI 변경·연동 인계](L1_WORKSPACE_VIEWER_UI_CHANGE_AND_MCP_VALIDATION_HANDOFF_r0002_20261120_KST.md)
- 대상: 기존 Linux MCP 프로젝트 whpark-mcp. 실제 등록 저장소·브랜치·소스/실행 호스트·설치 경로는 현장에서 읽기 확인해 확정. 임의 절대 경로나 새 서버를 가정하지 않아요.
- 현재 상태: MCP 확장 미구현, 운영 설치/연결 시험 NOT_RUN. 이 파일 게시가 MCP 설치·실행 트리거는 아니에요.

## 2. 기존 기능부터 확인하고 최소 확장

한 번의 읽기 조사로 기존 MCP의 tool 목록/계약, host routing, 호출 identity·권한, Work/Job 결과 조회, 스킬 설치 manifest, Viewer의 기존 health/읽기 API와 진단 코드를 대조해요. 이미 유효하게 확인한 결과는 재사용해요. 기존 도구로 가능한 항목은 REUSE/CONNECT, 실제 결손만 최소 EXTEND로 구분해 주세요.

기존 관측상 Agent 실행 환경과 실제 Linux 운영 호스트가 달랐고 READ/PLAN만 노출된 사례가 있어요. 따라서 MCP 서버 자신의 ping·파일 존재를 대상 Linux의 증거로 사용하면 안 돼요. 현재도 같다고 단정하지 말고 요청 대상과 관측 대상의 동일성을 먼저 확인해요. 대상 불일치/미접근이면 TARGET_UNREACHABLE 또는 TARGET_MISMATCH로 답하고, 로컬 컨테이너 상태로 대신 성공하지 않아요.

| 진단 묶음: 이름은 개념명, 실제 tool 이름 아님 | 수집할 실제 근거 | 답변에서 구분할 것 |
|---|---|---|
| capability/status | 기존 tool과 허용 read 작업, 실제 실행 대상 identity, 관측 시각 | 도구 노출 / 실행 권한 / 대상 호스트 접근 |
| installed skills | 설치 manifest·버전·파일 digest, 필요 시 실제 로드된 버전 | 공개 ZIP 존재 / 설치됨 / 실행 프로세스에 로드됨 |
| Viewer read probe | 기존 서비스 응답·권한·허용 read API의 응답 형식 | 프로세스 존재 / 연결됨 / 문서 조회 성공 |
| Work/Knowledge mapping | 기존 Work/Evidence·지식 ID·revision/published mapping에서 허용된 참조 | 후보 존재 / 검증 / 게시·readback 확인 |
| document/MSC probe | 승인된 대표 문서와 기존 B형 MSC의 존재·등록 hash·형식/허용 asset | 파일 존재 / API 응답 / 실제 화면 상호작용 시험 |
| gate/report | 기존 B1~B3/E3~E4 시험 결과·기준 revision·시각 | 설정 정적 확인 / 합성 시험 / 실제 호스트 시험 |

새 tool이 꼭 필요하면 기존 MCP 명명·인증·결과 계약에 맞춰 좁은 읽기 진단으로 추가해요. 임의 shell, 임의 URL, 임의 filesystem 경로, enqueue/retry/cancel, 분석·변환·게시·설치·서비스 시작 기능을 이 조회에 넣지 않아요. UI에서 반환한 URL도 서버의 기존 허용 대상에 매핑해 검증하며 임의 네트워크 탐색을 허용하지 않아요.

## 3. 요청·관측·응답 계약

- 사용자는 요청 한 번으로 가능한 항목 전체를 받고, 실패 지점마다 질문을 되풀이하지 않아요. 문서/MSC 대상은 명시한 기존 Work/문서 식별자 또는 현장에서 사전 등록한 대표 진단 대상으로 한정해요. 적합한 대상이 없으면 대표자료 없음으로 반환하고 새 Work·자료를 만들지 않아요.
- 실제 도구 이름·필드·영속 스키마는 기존 구현을 먼저 재사용해요. 아래 정보는 필요한 의미이지 신규 DB/원장 스키마 확정이 아니에요.
- 결과에는 요청 대상의 안전한 alias, 관측 시각, 관측 대상 일치 여부, 설치/로드 구분, 항목별 판정·짧은 reason code, 검사 방식, 근거의 현재성, 수행하지 못한 항목과 다음 한 행동이 필요해요.
- 시험 판정은 PASS/FAIL/SKIP/NOT_RUN. 상태/존재 확인 불가에는 UNKNOWN 또는 NOT_VERIFIED와 이유를 함께 표시해요. 미실행·권한 없음·timeout·응답 불완전을 PASS/FAIL로 임의 치환하지 않아요.
- 파일 존재·HTTP 200·Job DONE/SUCCESS만으로 문서 의미·분석·MSC 렌더·보안 게이트 PASS를 선언하지 않아요. 동일 revision에 대한 기존 유효 결과인지 확인해요. 현재성과 대상이 맞지 않는 과거 결과는 STALE/기존 결과로 표시해요.
- HTTP/read 검사와 브라우저 렌더/키보드·터치 시험을 분리해요. 기존 승인된 브라우저 진단 수단이 없으면 렌더/조작=NOT_RUN. 새 headless 브라우저 설치나 서비스 기동을 조회의 숨은 부작용으로 실행하지 않아요.
- 각 probe에 timeout·응답/파일 크기·조회 개수 한도, 취소와 부분 결과를 적용해요. 일부 실패가 나머지 유효 결과를 지우지 않도록 해요. 검사 도중 revision이 바뀌면 일관된 통합 PASS 대신 SNAPSHOT_CHANGED/재확인 필요를 반환해요.
- 조회로 Work/Evidence/Knowledge/Job 큐·원본을 쓰지 않아요. 기존 감사 기록은 기존 정책대로 남기되 내용·토큰을 로그에 복사하지 않아요. 진단 캐시가 있으면 대상·권한·revision에 묶고 관측 시각/유효성을 표시해요.

## 4. 모바일 Agent의 답변

Agent는 서버의 기존 user_summary/display를 우선 그대로 전달해요. 결과를 추정·재구성하거나 UNKNOWN을 정상으로 바꾸지 않아요. 기본 답변은 한국어 한두 문장 + 한 줄 판정, 자세한 근거는 명시적 상세 조회에서만 제공해요.

표시용 숫자: 1=PASS, 2=FAIL, 3=NOT_RUN, 4=BLOCKED/권한·접근 차단, 5=UNKNOWN/NOT_VERIFIED, 6=SKIP. 새 영속 enum이 아니라 모바일 표시 규칙 후보예요. 순서를 항상 함께 표시해 숫자 의미를 잃지 않아요.

합성 예시:

> Viewer API 연결은 확인했지만 실제 MSC 화면 시험은 실행하지 못했어요. 다음은 등록된 MSC의 격리 열람 시험이에요.
> 설치=1 로드=5 API=1 문서=1 MSC화면=3 보호=5 공유=3

이 예시는 실제 결과가 아니에요. B1/B2/B3는 상세 응답에서 각각 유지하며 ‘보호’ 집계가 일부 PASS를 전체 PASS로 덮지 않도록 해요. 설치 버전 문자열도 허용된 정보인 경우에만 함께 표시해요.

코드·문서 본문·상세 MSC·로그·실제 절대 경로·호스트 URL·개인/고객정보·credential은 모바일 반환에 넣지 않아요. 현재 승인된 MCP 응답 범위에서 허용된 상태만 제공하고, 자동 반출 권한을 새로 만들지 않아요. 반출 제한 근거는 업무 호스트에서 보존해요. 새 외부 수신 서버·전송 원장·자동 watcher는 이 요청 범위가 아니에요.

## 5. 개발·시험·적용 순서

1. 실제 대상 저장소·브랜치·revision·기존 API/도구·권한을 읽기 확인하고 동일 현장 Work에 기록해요. whpark-mcp라는 폴더명만으로 소스/운영 호스트를 동일시하지 않아요.
2. 기존 조회 기능별 재사용 표와 부족한 read probe만 설계해요. 호스트 자료가 없으면 가능한 순수 진단/표시 모듈과 합성 시험을 먼저 개발해요.
3. 허용된 개발 환경에서 구현·관련 회귀·후보 패키징·변경점/rollback을 마무리해요. 기존 Work/Evidence/Knowledge·Job Runner는 변경하지 않아요.
4. 실제 등록·배포·MCP 재시작은 해당 호스트의 유효 권한 범위를 확인해 적용하고, 범위 밖 단계만 BLOCKED로 남겨요. 문서 전달만으로 설치/활성 완료를 보고하지 않아요.
5. Agent가 새로 노출된 도구를 실제로 발견하고 호출해 응답을 받는 경로를 시험해요. 개발 함수 자체시험, MCP 연결 시험, Agent 표시 시험을 각각 구분해요.

| 필수 회귀 | 기대 결과 |
|---|---|
| 실제 대상 호스트 vs Agent 컨테이너 불일치 | TARGET_MISMATCH, 다른 호스트 파일로 PASS 금지 |
| 미설치/설치됐으나 구버전 로드/로드 미확인 | 각각 구분, 공개 ZIP 버전으로 대체 금지 |
| 미허용 ID·경로 탈출·symlink·임의 URL·shell 인자·권한 없음 | 안전한 차단, 원문/credential 노출 0 |
| API timeout/오류/부분 응답, snapshot 변경 | 부분 결과·정확한 원인 코드, 전체 성공 오판 0 |
| 대표 문서/MSC 없음·SHA 불일치·잘못된 MIME | 실패/미확인 표시, 재분석·재생성·Job 재실행 0 |
| HTTP 200이지만 로그인 HTML 또는 오류 payload | 문서 조회 PASS 금지 |
| 브라우저 수단 없음·보안 결과 없음·오래된 결과 | NOT_RUN/NOT_VERIFIED/STALE 구분 |
| 민감 본문/로그/토큰이 오류에 포함됨 | 서버에서 제거, 승인된 상태 요약만 반환 |
| 반복 조회·재시도·도구 중복 등록 | 모델/분석/변환/큐/서비스 변경 0, 중복 tool 확장 방지 |
| Agent가 실제 호출해 기본/상세 응답 표시 | 항목 순서·판정·시각·다음 행동 유지, 큰 JSON 기본 노출 금지 |

## 6. 업무 GPT가 받을 결과

대상 소스/브랜치/revision, 재사용·변경 파일, 실제 tool 계약과 허용 범위, 합성/호스트/MCP/Agent 시험별 PASS·FAIL·SKIP·NOT_RUN, 미확인, 후보 패키지 digest, 설치/활성 여부, rollback, 다음 한 행동을 업무 환경 Work에 남겨 주세요. 상세 현장 근거의 외부 업로드는 요구하지 않아요.

요청 완료 기준은 문서 작성이 아니라 실제 MCP→Agent 응답까지예요. 단 현장 권한/접근이 막혔다면 개발·합성 시험·패키지를 완료하고 실제 차단 구간과 실행 가능한 다음 한 행동을 명확히 남겨 주세요.

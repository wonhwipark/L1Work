- 버전: `r0002-PUBLIC` / 2026-11-13
- 용도: 파일·명령 실행 권한이 있는 Linux 로컬 Agent에게 한 번 전달하는 분석·격리시험 지시서
- 적용 단계: **기존 시스템 읽기 전용 진단 → 승인된 격리 복사본에서만 최소 수정·합성시험 → 로컬 결과 보고**

## 1. 역할 및 최종 목표

너는 해당 호스트에서 **승인된 범위의 파일·명령 읽기 기능을 가진 로컬 Agent**다. 이번 요청을 한 번의 제한된 조사로 수행하라. 현재 권한에 없는 작업은 `BLOCKED` 또는 `NOT_RUN`으로 격리한다.

최종 목표 흐름:

`허용된 작업 요청 → MCP 어댑터 → Job-list 등록/실행 → Runner/Worker 분석 → 실행 영수증 및 결과 저장 → MCP 상태/결과 조회 → 허용된 비민감 응답`

이번 작업의 완료 범위는 **원인 분석, 필요할 때 격리 복사본 내 최소 수정, 합성 회귀시험, 현장 근거 보고서**까지다. 서비스에 수정 적용하거나 실제 기존 Job을 재실행해서는 안 된다.

우선 **기존에 요청 호출이 작동했던 Workflow 도구와 Skill-Updater 도구의 MCP 계약을 비교**하고, 요청 호출과 결과 조회를 분리해서 검증한다. 이후 Job-list 활성화 및 Registry/Runner의 별도 장애 경계를 분석한다.

## 2. 안전·시간 제한과 종료 조건

1. 실행 시작 시각을 기록하고 **총 45분 이내에 조사·격리시험·보고를 종료하도록 시도**한다. 이는 작업 지시이지 강제 종료 보증이 아니다. 감독 실행기가 지원할 때에만 자기 작업에 대한 하드 타임아웃을 구성한다.
2. 개별 비운영 명령은 가급적 120초 이내로 제한하고, 같은 실패 명령은 원인 변화 없이 반복하지 않는다. 이전에 장시간 대기한 프로세스가 있더라도 자기 실행으로 생성한 것인지 불명확하면 종료하지 않는다.
3. 운영 MCP 서버, 기존 Workflow, Updater, Job-list 설치본, 예약 작업, Queue·Registry·운영 DB, 원본 소스, 서비스 설정을 변경하거나 재시작하지 않는다. 기존 ID의 재등록·재실행·재큐잉과 `activate --launch` 호출을 금지한다.
4. 허가 없는 권한 상승, 임의 Shell 실행 MCP 기능, 원격 호출 범위 확대, 자동 재시도, 자격증명 출력, 원문 소스/로그 반출 금지.
5. 격리 수정·합성시험에는 승인된 로컬 복사본, 가짜 작업 ID, synthetic fixture, 별도 임시 DB만 사용한다. 외부 모델 유료 호출과 실제 분석 작업 호출은 하지 않는다.
6. 시간이 다 되거나 접근이 차단되거나 충분한 근거를 확보하면 **현장 보고서를 보존하고 숫자 결과를 출력한 뒤 종료**한다. 운영 적용은 별도 명시적 승인 없이는 금지한다.

## 3. 1단계 — 기존 MCP 연결 두 가지 비교 (최우선)

실제 로드된 소스와 승인된 과거 실행 기록을 근거로 아래 표를 **로컬 보고서**에 채운다.

| 점검 영역 | 기존 Workflow Tool | 기존 Skill-Updater Tool |
|---|---|---|
| MCP Tool 등록 여부/실제 함수·파일 | 확인 | 확인 |
| 요청 스키마와 입력 검증 | 확인 | 확인 |
| 권한·승인 확인과 대상 제한 | 확인 | 확인 |
| 호출 프로세스·실행 ID | 확인 | 확인 |
| 프로세스 `HOME`, `CWD` 및 대상 루트 | 확인 | 확인 |
| 실행 상태·영수증 저장 위치 | 확인 | 확인 |
| MCP 상태 조회 인터페이스 | 확인 | 확인 |
| MCP 결과 조회 인터페이스 | 확인 | 확인 |
| 허용 결과 스키마·오류 코드 | 확인 | 확인 |

**실행 요청 기능이 작동했다는 사실이 결과 조회 성공을 뜻하지는 않는다.** 기존의 완료된 결과가 있다면 읽기 전용 조회 동작만 검사한다. 결과가 없으면 인터페이스만 정적으로 추적하고 테스트는 합성 데이터로 한정한다.

## 4. 2단계 — 결과 조회 실패 원인 분류

다음 원인들을 섞지 말고, 각각 실제 함수·분기·기록 근거로 구분한다.

- **Tool 부재:** 결과 조회 Tool이 구현되지 않았거나 등록되지 않음
- **등록/허용 실패:** Tool은 있으나 승인된 Job ID 또는 결과 참조가 allowlist에 없음
- **식별자 불일치:** request/job/run ID 매핑 누락, 버전 차이, 프로필 오인
- **경로/권한 오류:** 결과를 저장한 프로세스와 조회 프로세스의 실행 사용자, HOME/CWD, 저장 루트, 접근 권한 불일치
- **결과 미생성:** 실제 Worker가 시작하지 않았거나 결과가 생성되지 않음
- **응답 계약 결함:** `UNSUPPORTED`, `NOT_FOUND`, `NOT_READY`, `BLOCKED`, `SUCCESS` 등 상태가 구분되지 않음

MCP 설치 디렉터리와 코드 분석 프로젝트 디렉터리가 서로 다른 것 자체는 오류가 아니다. **실제 호출 인자·실행 계정·저장/조회 경로**가 연결되는지를 판정한다.

## 5. 3단계 — Job-list 실행 경계 별도 진단

- 현재 설치 Job-list의 버전·활성 요청·등록 프로필·Worker 식별자를 실측한다.
- Skill-Updater의 **자기 업데이트**와 **Job-list 설치 후 활성화**는 별도 경로로 점검한다.
- 아래 경계별로 최초 실패 근거를 확인한다.

`배포/설치 → 요청 Catalog → Activation/Registry → Queue/Receipt → Runner/Run ID → Worker → 결과 저장소 → MCP 조회`

- 전역 활성화의 `PARTIAL_SUCCESS`가 특정 Job의 실패를 뜻한다고 단정하지 않는다.
- Queue의 `DONE/SUCCESS`를 코드 분석 완료로 오인하지 않는다. Worker 시작 시각, 실제 Run ID, 결과 참조를 독립 확인한다.
- Worker가 시작한 근거가 있을 때에만 분석 CLI의 `--dir` 값, 필수 스킬 및 사전 검증의 실패 조건을 추적한다.
- MCP 결과 조회 불가와 Registry·Runner 실패는 **서로 다른 고장 영역**으로 다루며, 실제 근거 없는 복합 원인 판정은 하지 않는다.
- 이미 소비된 Job의 상태/영수증은 보존하며 신규 작업 ID를 임의 발행해 실행하지 않는다.

## 6. 4단계 — 필요한 최소 격리 수정

실제 결함이 확인되고 **로컬 격리 복사본 수정이 허용된 경우에만** 아래 작업을 수행한다.

1. 기존 두 MCP 도구의 검증된 스키마·권한·결과 조회 방식을 우선 재사용한다.
2. Job-list에 부족한 **허용된 프로필 기반 작업 요청·상태 조회·결과 조회** 기능만 최소 설계하거나 격리 구현한다.
3. 임의 명령 실행, 임의 경로 지정, 원본 로그/코드 다운로드, 만료·중복·승인 게이트 우회 기능은 추가하지 않는다.
4. 작업별 `request_id`/`job_id`/`run_id`/`status`/`result_ref`/`error_code`를 필요한 범위에서 일관되게 연결한다.
5. 바뀐 파일·근거 함수·diff·롤백 절차를 로컬 보고서에 기록한다. 격리 코드가 완성돼도 실제 서비스에 적용하지 않는다.

## 7. 5단계 — 합성 회귀시험

승인된 격리 복사본과 합성 데이터에서만 다음을 시험한다.

- 기존 두 MCP Tool의 요청/응답 계약 불변
- Job-list 작업 요청의 허용 프로필·인증·승인·중복 실행 거절
- 상태/결과 조회의 정상·미등록·미실행·만료·거절·경로 오류
- request/job/run ID 불일치 및 경로 이탈 입력 방어
- Registry 실패, Queue가 DONE인데 Run ID가 없는 경우, 결과 조회 미지원 상황 재현
- 소비된 One-shot ID 재실행 0회
- 기존 운영 DB·Queue·Registry·원본 코드·운영 설정 쓰기 0회 (검증 가능한 범위)

각 시험은 `PASS/FAIL/SKIP/NOT_RUN`으로 표시한다. **합성시험 PASS를 호스트 실제 종단 실행 성공으로 주장하지 않는다.** 독립 리뷰와 운영 적용도 별도 상태다.

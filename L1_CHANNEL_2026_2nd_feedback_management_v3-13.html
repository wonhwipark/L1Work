TL 평가 사용 가이드

권장 원칙: 대부분의 파트원은 TL Fast Review에서 끝내고, 예외적인 경우에만 상세 카드를 엽니다.

1. 3분 Quick Start

  1. TL Fast Review를 엽니다.
  2. 기본은 예외 우선으로 검토합니다.
  3. 1차 기대사항을 먼저 확인한 뒤 7~9월 성과·기여·영향·근거를 정리하고, 그 근거로 이행상태와 Action을 선택합니다.
  4. 3종 초안 생성으로 전달 Feedback / 11월 평가근거 / 10~11월 Action 초안을 만듭니다.
  5. 전달 Feedback을 확인·수정한 뒤 검토완료 + 다음을 누릅니다.
  6. 필요한 사람만 상세 카드로 이동합니다.

2. 1차 기대사항 이행 상태 선택 기준

상태언제 선택?
달성기대했던 결과나 행동이 현재 시점에서 확인됨
부분 달성일부 성과는 있으나 기대 수준 전체에는 아직 미도달
진행완료 시점이 아직 오지 않았고 계획에 따라 정상 수행 중
미흡(보완 필요)현재 시점 기준 기대했던 행동·결과가 부족해 명확한 보완이 필요
변경우선순위·업무 변경으로 기존 기대사항을 그대로 적용하기 어려움
확인 필요판단 근거가 아직 부족하여 상태 확정이 어려움

3. 3종 초안의 차이

파트원 전달 Feedback파트원에게 실제 전달할 문장. 생성 후 TL 검토 필요
11월 평가근거TL 비교·판단용 내부 메모. 파트원 전달문이 아님
10~11월 Action이번 피드백 이후 실제 확인할 단기 후속 행동
초안 생성 ≠ 평가 완료. 자동 생성 직후에는 초안 미검토이며, TL이 내용을 확인해야 검토완료로 처리합니다.

4. 근거 상태

미확보: 근거 없음 · 유형만: Jira/CL/UT 등 종류만 선택 · 식별자 있음: SOC-12345, CL 1234567, UT 92%처럼 나중에 다시 확인 가능한 값이 있음

5. 언제 상세 입력을 사용할까?

다음 경우에만 상세 카드를 권장합니다: 부분 달성/미흡, 추가 업무가 기존 목표를 대체한 경우, 승급 판단에 상세 근거가 필요한 경우, 공동 성과에서 개인 기여 구분이 어려운 경우, 자동 초안이 실제 상황을 충분히 표현하지 못하는 경우.

6. 저장 · 다른 PC 이동 · Undo

  • 입력은 현재 PC/브라우저에 자동 저장됩니다.
  • 다른 PC로 이동할 때는 다른 PC용 작업본 HTML 저장을 사용합니다.
  • 두 PC의 내용이 다르면 인원별 최신 수정본 병합을 우선 권장합니다.
  • 초안 생성/가져오기로 잘못 덮은 경우 카드의 직전 자동변경 되돌리기를 사용합니다.
  • 장기 보관용으로는 작업본 백업(JSON)도 함께 보관하는 것을 권장합니다.

7. 대표 사례

Case A · 정상 수행
계획대로 수행 + 주도 수행 + 품질/안정성 영향 + 기대사항 달성 + Jira/CL 식별자 → 초안 생성 → 검토완료.
Case B · 일부 미흡
Sub 인력 양성 등 일부 기대가 충분하지 않으면 부분 달성 또는 미흡을 선택하고 10~11월 Action으로 보완 방향을 연결합니다.
Case C · 긴급 추가 업무
긴급 상용 대응 때문에 계획된 리팩토링 일정이 조정됐다면 상세 카드에서 기존 업무 대체와 조정된 목표/일정을 함께 기록합니다.

8. 10~11월 Action과 중장기 성장 방향

10~11월 Action은 11월 평가 전까지 확인할 단기 실행 항목입니다. 중장기 성장 방향은 특정 반기로 한정하지 않고 역할·역량을 확장할 방향을 기록합니다. 두 항목은 같은 내용으로 중복 작성하지 않습니다.

9. 단축키

Ctrl+Enter: Fast Review에서 검토완료 + 다음 · Ctrl+S: 브라우저 즉시 저장

  1. 예외 우선으로 대상 확인
  2. 1차 기대 확인 → 7~9월 성과·기여·영향·근거 → 이행상태 판단 → Action 순으로 선택
  3. 3종 초안 생성
  4. Feedback 검토 후 다음 인원 이동

00

무엇을 하고, 무엇을 안 하는가

먼저 경계를 그어야 합니다. 이 Skill이 무엇을 대신하지 않는지가 무엇을 해 주는지보다 중요합니다.

한다
  • 현재 branch · 변경 · remote · ahead/behind 상태를 읽어 알려준다
  • 다음에 칠 Git 명령과 그 의미를 CLI LEARNING으로 보여준다
  • 보호 branch 직접 push, dirty push 같은 위험을 막는다
  • Fork에서 origin/upstream 역할이 뒤바뀌지 않았는지 검사한다
  • P4 Shelve CL을 분류해 이관을 돕는다
안 한다
  • PR 리뷰 — GitHub 웹에서 직접 합니다. v0.3.15에서 관련 action 7개를 제거했습니다
  • conflict 자동 해결 — 어느 쪽을 쓸지는 사람이 정합니다
  • force push · hard reset · 자동 rebase — 지원하지 않습니다
  • 묻지 않고 실행 — write는 preview가 먼저입니다
이 문서와 CLI 가이드의 관계

개념의 SSOT는 smp1900_Fork_Git_CLI_가이드입니다. "왜 origin이 정식이 아닌가", "왜 commit이 제출이 아닌가"는 거기에 있습니다.

이 문서는 그 위에서 Skill이 어디까지 개입하는지만 설명합니다. 두 문서가 어긋나면 가이드가 이깁니다.

01

세 개의 역할

가이드에서 헷갈리는 것이 "지금 어느 저장소를 건드리는가"였다면, 여기서 헷갈리는 것은 "지금 누가 결정하는가"입니다.

Skill dispatcher + helper

Python이 상태를 결정형으로 읽습니다. 모델은 그 결과를 설명할 뿐 추론하지 않습니다.

읽기 · 제시 · 차단
사람 당신

preview를 읽고 명령을 직접 칩니다. 되돌리기 어려운 결정은 전부 여기서 납니다.

판단 · 실행 · 책임
Git working tree · remote

실제로 바뀌는 곳. 사람이 명령을 치거나 --apply를 붙였을 때만 움직입니다.

변경 발생

Python이 구조 결정을 담당하고 모델은 그 JSON을 읽어 주는 구조라, 사내 게이트웨이의 저사양 모델에서도 판단이 흔들리지 않습니다. 모델이 workflow를 추론하지 않는 것이 설계 목적입니다.

02

요청 하나가 흐르는 길

자연어를 던지면 네 단계를 지납니다. 세 번째에서 반드시 멈춥니다.

  1. dispatcher가 의도와 상태를 결정한다

    정규식 기반이라 매번 같은 입력에 같은 결과가 나옵니다. 모델이 개입하지 않습니다.

  2. helper가 preview를 출력한다

    실행될 Git 명령, 그 의미, 막힌 이유(BLOCK)와 다음 단계(NEXT)를 함께 보여줍니다.

  3. 여기서 멈춘다

    preview를 읽고 당신이 판단합니다. 이 지점이 비협상입니다.

  4. 당신이 명령을 친다

    preview에 나온 Git 명령을 직접 치는 것이 기본입니다. --apply는 예외 경로입니다.

PowerShell
PS> py scripts/l1_github.py push === l1-github :: PUSH === Branch : feature/ABC-123-tx-fix Push : origin/feature/ABC-123-tx-fix CLI LEARNING: $ git push -u origin feature/ABC-123-tx-fix -> 작업 branch를 push remote에 올리고 tracking 설정 PREVIEW ONLY. Add --apply to run it.
Skill 읽기만 함 사람 위 명령을 직접 치면 끝
write chaining 금지

사용자 요청 1회당 write는 최대 1개입니다. commit 해줘는 commit까지만, push 해줘는 push까지만입니다.

helper가 NEXT를 출력해도 같은 턴에서 이어서 실행하지 않습니다. 다음 단계는 당신의 새 요청이 있어야 합니다.

03

CLI LEARNING — 이 도구의 핵심

명령을 숨기지 않는 것이 설계 의도입니다. 이 블록이 없으면 Skill은 그냥 블랙박스가 됩니다.

RUN/CHANGE preview는 항상 실제로 실행될 Git 명령과 그 명령이 무엇을 하는지를 한 줄씩 붙여 출력합니다. 가이드 03절의 다섯 단계가 그대로 대응됩니다.

Skill이 보여주는 것가이드 대응
git fetch upstream03절 ① 정식 최신 상태 받기
git switch -c feature/... upstream/dev03절 ① 기준은 항상 upstream
git add -u 또는 선택 파일03절 ② 올릴 파일 고르기
git commit -m "..."03절 ③ 내 PC에 기록
git push -u origin feature/...03절 ④ 내 Fork로 보내기
git merge upstream/dev04절 정식이 앞서갔을 때
읽는 법
preview에 나온 명령을 복사해서 치는 것이 정상 사용법입니다. 같은 명령을 세 번쯤 치고 나면 다음부터는 Skill을 부르지 않게 되고, 그게 이 도구의 목표 상태입니다.
04

막는 것들

helper가 BLOCK을 찍으면 그 자리에서 멈춥니다. 대부분 가이드 07절의 "자주 하는 착각"과 정확히 짝을 이룹니다.

BLOCK: dirty worktree push is disabled
commit 안 한 변경은 push되지 않습니다. 가이드 07절 "고친 파일이 있으니 push하면 올라간다"에 해당합니다. 이게 반복되면 commit과 push의 구분이 아직 안 잡힌 것입니다.
BLOCK: working changes exist on protected branch '…'
dev / main / master 위에서 작업 중입니다. 작업 branch를 먼저 파야 합니다. 보호 branch 목록은 .l1git/policy.json이 정합니다.
BLOCK: no staged files
고치기만 하고 git add를 안 했습니다. 가이드 03절 ②의 "고른다" 단계가 빠진 상태입니다.
BLOCK: textual conflict markers remain
<<<<<<< 가 파일에 남아 있습니다. VS Code Resolve in Merge Editor로 처리하세요. 가이드 05절.
BLOCK: detached HEAD
branch 이름 없이 특정 commit 위에 서 있습니다. 여기서 한 작업은 잃기 쉬우니 먼저 branch로 이동합니다.
BLOCK: merge is already in progress
이전 merge가 안 끝났습니다. 해결하거나 git merge --abort로 되돌린 뒤 진행합니다.
차단은 고장이 아닙니다

BLOCK은 Skill이 실패한 것이 아니라 지금 하려는 일이 의도와 다르다고 알려 주는 것입니다. preview의 NEXT 줄에 다음 행동이 같이 나옵니다.

정말 committed history만 올려야 하는 예외 상황에서만 push --allow-dirty를 씁니다. 일상적으로 쓰는 옵션이 아닙니다.

05

자주 쓰는 요청

명령을 외울 필요는 없지만, 무엇이 실행되는지는 항상 화면에 나옵니다.

이렇게 말하면이 action결과
지금 어디까지 했어?statusbranch · 변경 · base 대비 ahead/behind
수정 끝났어. 다음 진행해줘상태가 결정모델이 추론하지 않고 next_action을 따름
commit 해줘commitstage 범위 확인 → preview
push 해줘pushdirty · 보호 branch · Fork remote 검사 후 preview

이름이 헷갈리는데, 남의 코드를 보는 것이 아니라 내 branch가 PR을 올릴 상태인지 확인하는 점검입니다.

work branch인가 / conflict 없는가 / working tree 깨끗한가 / push tracking 있는가 / base보다 뒤처지지 않았나 — 다섯 개를 봅니다. PR 자체는 GitHub 웹에서 만듭니다.

06

정책은 저장소에 있다

base branch가 무엇인지, 어떤 branch를 보호할지는 Skill이 아니라 저장소가 정합니다.

<repo>/.l1git/policy.json
{ "schema_version": 1, "base_branch": "dev", "protected_branches": ["dev", "main", "master"], "workflow_mode": "fork", "remote_roles": { "base": "upstream", "push": "origin", "pr_target": "upstream" } }

Skill은 이 파일을 읽기만 합니다. 자동으로 만들거나 고치지 않습니다. URL · Token · 개인 경로는 스키마에서 거부되므로 저장소에 commit해도 안전합니다.

왜 여기
정책이 사람마다 로컬에 흩어져 있으면 반드시 갈라집니다. 저장소에 두면 clone하는 순간 같은 규칙이 적용됩니다. 파일이 없으면 기존 설정으로 fallback하고, 값이 다르면 policy를 쓰되 status에 충돌을 경고합니다.
07

무엇을 기록하는가

습득이 목표이므로, 아직 Skill에 기대고 있는 지점을 볼 수 있게 남깁니다.

PowerShell
PS> py scripts/telemetry_report.py --- HOW MUCH THE TOOL IS STILL DOING FOR YOU --- Write-capable runs : 42 Applied : 7 Apply rate : 16.7% --- WHAT THE SAFETY NET CAUGHT --- 5x BLOCK: dirty worktree push is disabled…
보이는 것읽는 법
Apply rate높으면 Skill이 대신 실행 중. 시간이 지나며 내려가야 정상입니다
반복되는 BLOCK아직 안 잡힌 개념. 같은 차단이 계속 뜨면 그 개념을 가이드에서 다시 봅니다
Malformed command lines모델이 잘못된 명령을 만든 횟수
기록하지 않는 것

자연어 요청 원문은 남기지 않습니다. BLOCK 사유의 인용부호 안 변수는 '<redacted>'로 치환되므로 branch · ticket · 경로가 로그에 남지 않습니다.

합격선은 없습니다. 주 1회 열어 추세만 봅니다.

08

자주 하는 착각

가이드 07절이 Git에 대한 착각이라면, 여기는 Skill에 대한 착각입니다.

  • Skill이 commit이랑 push를 해 준다 기본은 preview까지입니다. 화면에 나온 Git 명령을 직접 치는 것이 정상 사용법이고, --apply는 예외 경로입니다. 이 구분이 이 도구의 전부입니다.
  • Skill이 막았으니 뭔가 잘못됐다 BLOCK은 의도와 실제가 다르다는 신호입니다. dirty push 차단은 "commit 안 한 파일은 안 올라간다"를 알려 주는 것이지 오류가 아닙니다.
  • 한 번 요청하면 끝까지 진행된다 요청 1회에 write는 최대 1개입니다. commit 다음에 push가 필요하면 push를 다시 요청해야 합니다. 연쇄 실행은 의도적으로 막혀 있습니다.
  • Skill이 있으니 Git 명령은 몰라도 된다 반대입니다. Skill이 죽어도 일이 막히지 않는 것이 목표입니다. 그래서 명령을 숨기지 않고 매번 보여 줍니다.
  • PR 리뷰도 Skill로 한다 v0.3.15에서 리뷰 action 7개를 제거했습니다. 리뷰는 GitHub 웹에서 직접 합니다.
09

Skill이 안 될 때

Python이 죽든 게이트웨이가 막히든, Git 작업 자체는 막히지 않아야 합니다.

  1. 가이드를 엽니다

    smp1900_Fork_Git_CLI_가이드에 한 사이클이 순수 Git 명령으로 다 있습니다. Skill 없이 끝낼 수 있게 쓰여 있습니다.

  2. 막혔을 때 순서

    git status → git remote -v → git log --oneline -5. 가이드 10절과 같습니다.

  3. 그래도 모르겠으면 멈춥니다

    명령을 더 던지지 말고 위 세 개의 출력을 그대로 복사해서 물어보는 편이 훨씬 빨리 풀립니다.

되돌리기

Skill은 force push · hard reset · 자동 rebase를 하지 않으므로, Skill이 만든 상태는 대부분 git reflog로 되짚을 수 있습니다. 되돌리기는 가이드 06절에 있습니다.

PowerShell
PS> py scripts/l1_github.py status # 상태만, 아무것도 안 바꿈 PS> py scripts/l1_github.py help # Git 실행 없음
Skill 애매하면 이 둘로 돌아옵니다

L1 지식 설계 · 전체 동작 플로우

두 진입 모두 개인 Workspace에 분석을 보존하고 검증 지식을 그룹에 반영하는 5개 영역·13단계

A · Updater 직접 분석

Procedure/Feature 기반 분석 요청 → 기존 Work 선택·재개 → 분석·초안·근거를 개인 l1-workspace에 보존 → 지식 후보 검토.

B · l1-fix-workflow 업무 결과

코드·이슈·설계 분석 → l1-workspace의 기존 Work/Evidence → Updater에서 재분석 없이 지식 후보·검토 결과를 같은 Work에 연결.

A·B는 같은 13단계에 들어오는 두 진입입니다. Updater는 A의 요청 접수와 ⑦의 지식 후보 검토에 관여하며, 두 스킬 모두 ⑥ l1-workspace에 결과를 저장·갱신하는 주체이며 기존 Kernel/저장 경로를 재사용합니다. 그룹 반영 여부와 별개로 개인 분석 이력을 보존합니다.

각 번호 카드를 선택하면 책임과 검증 범위를 확인할 수 있습니다. 화살표는 설계된 데이터·책임 흐름으로, 실행·Knowledge 게시·RAG 실증 완료 표시가 아닙니다.

정본 역할 구분

개인 업무용 l1-workspace

Updater 직접 분석과 Workflow 결과의 분석·초안·source revision·Evidence·결정·미확인을 같은 Work에 보존. 실제 업무용 개인 PRIVATE Git이며 동명 GitHub.com 저장소로 추정하지 않음.

그룹 공용 l1sw-dev-knowledge

팀이 사용하는 스킬과 관리하는 검증 기술 지식. 승인된 HLD·상세 설계·MSC·이슈 지식을 기존 경로로 반영. 실제 저장 위치·게시/readback·원래 Work 연결은 각각 확인.

설계 흐름을 표시한 화면입니다. 코드 분석, 그룹 게시, 검색·RAG 본문 소비의 실제 E2E 성공을 의미하지 않습니다.
